# Codex 电脑控制 / Edge 浏览器控制卡顿的代理修复

[English & installation commands](README.md)

这个项目分享一次 Windows 上已复现、已验证的修复：电脑和浏览器已经使用本地代理，但 Computer Use 的后台进程没有继承代理设置，导致每次读取网页固定等待约 21 秒，多步操作经常超时。

这是社区解决方案，适用于**已经有可用本地代理**、且遇到类似症状的用户；它本身不提供代理，也不适用于所有浏览器故障。

## 什么现象值得检查

- 能识别 Edge 和标签页，打开网页也快，但读取内容、截图或点击经常卡住。
- 单次读取反复耗时约 21 秒，多步操作超过 30 秒后报超时。
- 重启浏览器、重启客户端、重新启用或重装扩展仍然没有改善。
- 桌面应用或手机投屏的截图与点击正常。

仅凭 `Debugger unattached` 或一次超时，不能断定就是本项目解决的问题。在实测案例中，扩展和本地通信注册检查均通过；进一步观察到控制进程直连 `ab.chatgpt.com:443` 一直等待，而通过现有代理约一秒即可完成 HTTPS 连接。

## 修复结果

测试环境：Windows、Codex Desktop `26.1027.3384.0`、运行组件 `26.1027.30824`、Edge `151.0.4129.72`、ChatGPT 扩展 `1.26.1021.11019`。

| 操作 | 修复后实测 |
| --- | ---: |
| 打开网页并读取内容 | 1.24 秒 |
| 点击链接并读取跳转页面 | 1.94 秒 |
| 网页截图 | 0.061 秒 |
| 读取网页标题和可见标题元素 | 0.039 秒 |

这是单个案例的测量结果，不是对其他电脑的速度保证。

## 原理与安装

启动器把你现有的代理设置传给**同一套官方 Computer Use 组件**。每次启动时，它读取客户端生成的最新组件配置，保留原始命令、参数、权限引导和受信服务设置，不修改浏览器权限、安全检查、扩展文件或客户端程序。

使用独立名称 `cua_repl_proxy` 很关键：在测试版本中，客户端启动时会删除对内置 `cua_repl` 名称的自定义覆盖。直接改那个名称，看似配置成功，重启后又会失效。

具体安装命令见 [英文 README 的 Install 部分](README.md#install)：

1. 下载本项目，在项目目录打开 PowerShell。
2. 运行提供的命令，复制启动器并生成与你电脑路径匹配的配置片段。命令不会覆盖你的配置文件。
3. 备份用户 `.codex/config.toml`，追加生成的片段。将示例 `7890` 改为你真正使用的 **HTTP 代理端口**，不要盲目照抄端口。
4. 完整退出并重新打开 Codex。
5. 告诉助手使用 `mcp__cua_repl_proxy.js`，实际测试读取、点击和截图。原来的内置入口仍然保留，不能误用它来判断新入口是否生效。

还可以把英文 README 中的简短使用偏好追加到全局 `.codex/AGENTS.md`，让后续聊天优先选新入口。不要覆盖原有说明，也不要复用其他聊天的标签页编号和元素编号。

保持现有代理运行。代理端口变化或外层 Node 可执行文件在升级后被移除时，需要更新对应配置。

## 验证、卸载与隐私

- `node --test launcher.test.mjs`：运行本地回归测试，不连接真实浏览器。
- `node launcher.mjs --check`：检查配置解析；不能代替实际网页操作验证。
- 如有 Codex CLI，可检查 `codex mcp list --json` 中单独的 `cua_repl_proxy` 项。不要公开完整输出，其他服务可能包含密钥。
- 卸载时只删除 `config.toml` 中的 `[mcp_servers.cua_repl_proxy]` 及其子表，移除可选的全局说明，再重启客户端。内置入口不受影响。

项目只包含通用启动器、测试和说明，不包含个人电脑配置、私人日志、账号资料或截图。提交问题时，请提供版本和去除隐私后的耗时信息。
